# Table Reorder 文書同期 差分分析

## 位置づけ

本書は `docs/plans/table-reorder/table-reorder-document-sync-plan.md` の **Phase 1: 文書原則と現行仕様との差分を確定する** の成果物である。

対象は現在の `main` に実装済みの利用者向け振る舞いと既存文書の差分確認に限定する。

本書では次を行わない。

- 要件定義書・基本設計書そのものの更新。
- 通常操作の基本設計書の新設。
- 製品コードやテストの変更。
- 現行仕様の変更。
- 未実装の将来仕様の追加。

後続の文書更新では、本書で整理した差分と分類を参照する。正本となる実施計画自体は変更しない。

## 分類基準

| 分類 | 本書での意味 | 後続での扱い |
|---|---|---|
| What | 利用者に何を提供するか、何を保証するか、どの制約を満たすか | 要件定義書 |
| How | 利用者がどの画面・入口・手順・状態・案内で要件を実現するか | 基本設計書 |
| Technical How | DOM、API、ファイル、関数、内部状態、ライブラリ設定など、プログラムとしてどう実現するか | 要件定義書・基本設計書には反映しない |

一つの観点に What と How の両方がある場合は、内容を分離してそれぞれの文書責務へ割り当てる。

## 文書別の確定事項

### 基本要件

現行仕様との主な事実差分は、対応Tableブロックが Core Table のみではなく Flexible Table Block を含む点である。

また、現在の文書には次のような利用者向け How または Technical How が含まれている。

- hover時のハンドル表示方法。
- ハンドルからのドラッグ開始方法。
- タッチモード内の具体的な操作手順。
- dnd-kit版とSortableJS版の実現方法比較。

後続では、提供する操作方法・保証する結果・利用上の制約という What と、具体的な利用者向け How を分離する必要がある。

### アクセシビリティ要件

現行仕様との主な事実差分は、対象を Core Table のみとしている点である。

キーボード完結、ドラッグを必要としない単一ポインター操作、論理的なアクセス順、フォーカス可視性・遮蔽防止、操作案内、支援技術への情報提供という主要な What は、現在の `main` の振る舞いと大きく矛盾していない。

通常操作を再定義せず、アクセシビリティ上追加で満たす必要がある性質に絞るという責務も維持できる。

### アクセシビリティ基本設計

現行仕様との主な事実差分は次の2点である。

1. 対象を Core Table のみとしている。
2. 利用者向けメッセージの一部が現在の画面表示と一致していない。

また、通常のPC・タッチ操作の How が相当量含まれているため、新設する通常操作基本設計との責務整理が必要である。

キーボード操作への入口、開始・移動・確定・キャンセル、フォーカス維持・復元、Focus Not Obscured、初回案内、支援技術への情報提供については、現在の実装と大枠で一致しており、未実装の将来仕様として扱う必要はない。

## Technical How として反映しない事項

現行仕様の確認時に把握した次の内容は、利用者向けの要件・基本設計へは持ち込まない。

- 対応ブロックごとの `rowspan` / `rowSpan` 属性名の違い。
- DOMの探索順序や `ownerDocument` / `defaultView` の扱い。
- SortableJSの生成・破棄・再生成方法。
- 一時的なDOM行順の復元と属性更新の内部手順。
- controller、hook、HOC、ファイル単位の責務分割。
- CSS selector、class名、`sticky` / `fixed` 等の具体的な配置手段。
- 具体的なARIA属性、live regionのDOM構造、通知更新処理。

## Phase 1 の結論

Phase 1 の範囲で、後続更新候補はすべて What、非技術的な How、または非反映とする Technical How に分類できた。

主要な事実差分は次のとおりである。

- 対応範囲が Core Table だけでなく Flexible Table Block に拡張されている。
- 通常操作基本設計が存在せず、通常操作の How が基本要件とアクセシビリティ基本設計へ分散している。
- アクセシビリティ基本設計を自然言語メッセージの正本としている一方、現在の画面表示には複数の文言差分がある。
- その他のキーボード操作、結合セル制約、フォーカス、支援技術への情報提供、iframe / non-iframeの主要な利用者向け仕様は、既存文書と現行実装の大枠が一致している。
- 実装内部の仕組みは Technical How として、要件定義書・基本設計書の同期対象から除外する。

未実装の将来仕様は本分析へ追加していない。

ここまでを Phase 1 の成果とし、要件定義書・基本設計書の実更新には進まない。
