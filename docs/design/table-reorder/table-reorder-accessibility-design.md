| 項目 | 内容 |

| 対象 | WordPress Gutenberg のコア Tableブロック |
| 文書種別 | 基本設計書 |

| 関連要件定義書 | `table-reorder-accessibility-requirements.md` |

## 2. 文書の目的と責務

本書は、Table Reorderアクセシビリティ要件定義書を、現在のTable Reorder実装構成とdnd-kit APIを前提に実現するための基本設計を定める。

既存のTable Reorder基本設計書を基礎とし、本書では次だけを追加で扱う。

- ポインター専用Sensor構成へのキーボード操作追加
- 並べ替えモード中の操作案内
- キーボード並べ替えの状態と操作フロー
- スクリーンリーダー通知
- 確定、キャンセルおよび明示的なモード終了時のフォーカス管理

ポインターDnD、行データ更新、Undo、`rowspan`判定、DOM測定、iframe・非iframe対応およびDnD視覚表現は既存設計を正とし、本書では変更点だけを定義する。

## 3. 設計原則

1. 既存のドラッグハンドルをポインター操作とキーボード操作の共通UIとして使用する。
2. 現在の`@dnd-kit/react`、`@dnd-kit/dom`および`@dnd-kit/react/sortable`の構成を拡張し、削除前の旧APIを復活させない。
3. `PointerSensor`による既存ポインターDnDは維持する。
4. キーボード操作は、行の高さや座標に依存せず、本文行のindexを基準に一行ずつ移動先候補を変更する。
5. キーボード状態では移動後の行indexを保持し、既存commit処理へ渡す直前に方向を考慮して挿入indexへ変換する。
6. ポインター操作とキーボード操作は、同じ移動可否判定、確定処理およびUndo単位を共有する。
7. ドラッグ中またはキーボード操作中にTableブロックの`body`を更新せず、有効な確定時だけ一回更新する。
8. 案内、通知およびフォーカス管理はTable Reorder機能内へ限定し、汎用基盤を新設しない。
9. iframe・非iframeのどちらでも、対象Tableブロックが存在する編集領域を基準にDOMとフォーカスを扱う。

## 4. UI設計

### 4.1 並べ替えモード

並べ替えモード中は、既存のドラッグハンドルに加えて短い操作案内を表示する。

```text
ブロックツールバー
[並べ替えを終了]

ハンドルをドラッグして移動できます。
キーボード: Enter / Space で開始、↑ ↓ で移動、
Enter / Space で確定、Escape でキャンセル

   ┌────────┬────────┐
⠿  │ セル   │ セル   │
   ├────────┼────────┤
⠿  │ セル   │ セル   │
   └────────┴────────┘
```

- 案内は並べ替えモード中だけ表示する。
- 案内はTableブロックの編集UIと同じ編集領域に表示する。
- 案内要素へ一意なIDを付け、各ハンドルから`aria-describedby`で参照する。
- 案内自体をライブリージョンにはしない。

### 4.2 ドラッグハンドル

既存の`SortableRow`が描画するボタンを共通ハンドルとして使用する。

- `aria-label`は現在の本文行indexを使い、「N行目を並べ替える」とする。
- `aria-describedby`で操作案内を関連付ける。
- 操作中であることは、必要に応じて`aria-pressed`または同等の状態属性で表す。
- `rowspan`範囲内の行はポインターDnDを開始できない状態を維持する。
- 利用不能行で理由を伝える必要があるため、ネイティブ`disabled`だけに依存してフォーカス不能にはしない。ポインター開始を無効化しつつ、`aria-disabled="true"`で状態を表し、キーボード開始時に理由を通知できる構成とする。

## 5. 状態設計

既存の状態に、キーボード操作用の一時状態を追加する。

| 状態 | 説明 |
|---|---|
| 通常 | セル編集を行う状態。ハンドルと案内は表示しない。 |
| 並べ替え待機 | ハンドルと案内を表示し、ポインターまたはキーボード操作を開始できる状態。 |
| ポインターDnD中 | 既存のポインターDnD状態。 |
| キーボード操作中 | 一つの行と移動先候補をキーボードで操作している状態。 |

キーボード操作中は、少なくとも次を保持する。

- 移動元行ID
- 移動開始時の行index
- 現在の移動後行index（`destinationIndex`）
- 現在の移動先候補
- 開始時にフォーカスされていたハンドル
- 最後に通知した内容

`insertionIndex`はキーボード状態の主状態として保持しない。既存のdrag sessionへ候補を渡す際に、`sourceIndex`と`destinationIndex`から算出する。

ポインターDnDとキーボード操作は同時に開始しない。一方が進行中の場合、他方の開始操作は受け付けない。

## 6. コンポーネント設計

### 6.1 `with-table-reorder.tsx`

- 既存どおり並べ替えモードを管理する。
- 並べ替えモード中の操作案内を描画する。
- 案内IDを`TableReorderController`へ渡す。
- 利用者が「並べ替えを終了」ボタンを明示的に操作した場合だけ、通常表示へ切り替わったモード切替ボタンへフォーカスを戻す。
- セル編集への復帰、対象ブロックの選択解除、別ブロックの選択または削除による終了では、移動済みのフォーカスを尊重し、モード切替ボタンへの復元を行わない。
- 明示的な終了時でも復元先が存在しない場合はフォーカス処理を省略する。

### 6.2 `table-reorder-controller.tsx`

- 既存の`PointerSensor`構成を維持する。
- キーボード操作の開始、移動、確定およびキャンセルを調整する。
- 既存の`beginTableReorderDrag`、`updateTableReorderDragTarget`、`commitTableReorderDrag`を、キーボード操作からも利用できる形へ整理する。
- キーボード状態の`destinationIndex`を、既存処理へ渡すための`insertionIndex`へ変換する。
- `rowspan`制約、同位置、範囲外および`tbody`外の判定をポインター操作と共有する。
- 有効なキーボード候補では、既存の`TableReorderDragVisuals`を使って移動先と回避表示を示す。
- スクリーンリーダー通知と、確定・キャンセル後の行ハンドルへのフォーカスを管理する。

### 6.3 `sortable-row.tsx`

- 既存の`useSortable`登録と`handleRef`を維持する。
- `onKeyDown`を受け取り、ハンドルのキー操作をcontrollerへ渡す。
- `aria-describedby`、`aria-disabled`および操作中状態を付与する。
- `rowspan`により移動不能な行でも、理由を確認できるフォーカス可能な操作要素として扱う。
- Table属性更新、移動可否判定、通知内容の組み立ては持たない。

### 6.4 キーボード操作モジュール

キーボード状態遷移と次の候補計算は、DOMイベント処理から分離した小さな純粋関数として実装する。

責務は次とする。

- 開始時は`destinationIndex = sourceIndex`として移動前位置を保持する。
- `ArrowUp`では`destinationIndex - 1`、`ArrowDown`では`destinationIndex + 1`を次候補とする。
- 先頭、末尾および`rowspan`禁止位置を判定する。
- 禁止位置を飛び越えず、現在候補を維持する。
- 有効候補を既存drag sessionへ渡す際、`destinationIndex > sourceIndex`なら`insertionIndex = destinationIndex + 1`、それ以外なら`insertionIndex = destinationIndex`へ変換する。
- 確定時に既存のcommit処理へ渡すtarget情報を生成する。

ファイル名は実装時に責務へ合わせて決定し、汎用`utils`ディレクトリは作成しない。

## 7. キーボード操作設計

### 7.1 開始

1. ハンドルで`Enter`または`Space`を押す。
2. ブラウザー既定のボタン動作とページスクロールを抑止する。
3. 対象行が移動可能か確認する。
4. 移動不能な場合は理由を通知し、待機状態を維持する。
5. 移動可能な場合は開始時の行順序、移動元情報および`destinationIndex = sourceIndex`を記録する。
6. キーボード操作中状態へ移行し、開始通知を行う。

### 7.2 移動

- `ArrowUp`は、現在の`destinationIndex`を一つ減らす。
- `ArrowDown`は、現在の`destinationIndex`を一つ増やす。
- 一回のキー入力につき候補変更は一回だけとする。
- 行の高さ、画面スクロール量およびdnd-kitの座標移動量は候補計算に使用しない。
- 有効な候補では、`destinationIndex`を方向に応じた`insertionIndex`へ変換し、既存の挿入線と行回避表示を更新する。
- 先頭、末尾または`rowspan`禁止位置では候補を変更せず、理由を一回通知する。

5行の表で3行目から開始する場合の例を次に示す。表記上の行番号は1始まり、内部indexは0始まりとする。

| 操作 | `sourceIndex` | 次の`destinationIndex` | 既存処理へ渡す`insertionIndex` | 表示候補 |
|---|---:|---:|---:|---|
| 開始 | 2 | 2 | 渡さない | 3行目のまま |
| 最初の`ArrowUp` | 2 | 1 | 1 | 2行目 |
| 最初の`ArrowDown` | 2 | 3 | 4 | 4行目 |

これにより、開始直後の最初の上下操作が同位置になることを防ぎ、どちらも一行分の移動候補になる。

### 7.3 確定

1. 操作中に`Enter`または`Space`を押す。
2. 現在候補が有効で、`destinationIndex`が`sourceIndex`と異なる場合だけ`body`を一回更新する。
3. 既存の行IDに基づき、移動後の同じ行のハンドルを特定する。
4. 視覚表現と一時状態を解除する。
5. 完了通知を行い、移動後のハンドルへフォーカスを維持する。

同じ位置の確定はno-opとし、Undo履歴を増やさない。

### 7.4 キャンセル

1. 操作中に`Escape`を押す。
2. `body`を更新せず、開始前の行順序を維持する。
3. 視覚表現と一時状態を解除する。
4. キャンセル通知を行う。
5. 開始時の同じ行のハンドルへフォーカスを戻す。

## 8. スクリーンリーダー通知設計

### 8.1 ライブリージョン

- Table Reorder機能内に、視覚的には非表示のライブリージョンを一つ配置する。
- 操作結果を順番に伝えるため、通常の通知は`aria-live="polite"`を基準とする。
- ライブリージョンは並べ替えモード中だけ存在させる。
- 通知文の更新だけを行い、DOMを複数箇所へ重複配置しない。

### 8.2 通知内容

| 場面 | 通知例 |
|---|---|
| 開始 | 「3行目の並べ替えを開始しました。全5行です。」 |
| 移動 | 「2行目へ移動します。全5行です。」 |
| 完了 | 「3行目を2行目へ移動しました。」 |
| キャンセル | 「並べ替えをキャンセルしました。3行目のままです。」 |
| 先頭・末尾 | 「これ以上上へ移動できません。」 |
| `rowspan`制約 | 「結合セルを分断する位置には行を移動できません。結合を解除してから並べ替えてください。」 |

位置は画面上の本文行順を1始まりで表す。

### 8.3 重複抑止

- 同じ候補位置が続く間は同じ移動通知を繰り返さない。
- 同じ禁止理由が続く間は同じ禁止通知を繰り返さない。
- 候補または禁止理由が変わった場合は、必要な通知を再度行える。
- WordPressの画面通知とライブリージョンが同じ文言を同時に二重読み上げしないようにする。

## 9. フォーカス設計

- ハンドル要素は行IDと対応付けて管理する。
- 行移動後にReactとGutenbergの再描画が完了してから、同じ行IDのハンドルへフォーカスする。
- フォーカス処理は対象Tableブロックの`ownerDocument`内で行う。
- iframe外のグローバル`document.activeElement`を前提にしない。
- 利用者が「並べ替えを終了」ボタンを明示的に操作した場合だけ、ブロックツールバーのモード切替ボタンへフォーカスする。
- セル編集への復帰、選択解除、別ブロック選択またはブロック削除によるモード終了では、既に移動したフォーカスを尊重し、フォーカス復元処理を開始しない。
- 明示的な終了時でもフォーカス対象が存在しない場合は例外を発生させず、フォーカス処理だけを省略する。

## 10. `rowspan`制約と既存処理の共有

キーボード操作は、既存の`drag-session.ts`と`rowspan.ts`が扱う制約を共有する。

- `rowspan`範囲に含まれる行から開始しない。
- 結合範囲の途中を移動先にしない。
- 結合範囲を越える移動を許可しない。
- 禁止位置では候補、挿入線および行回避表示を更新しない。
- 禁止操作では`setAttributes`を呼ばない。
- `colspan`だけを含む行は、既存仕様どおり許可する。

キーボード専用の別制約は追加しない。

## 11. iframe・非iframe対応

- 案内とモード切替ボタンはWordPressのReact UIとして描画する。
- ハンドル、ライブリージョン、フォーカス対象およびキーボードイベントは、対象Tableブロックが存在する編集領域を基準に扱う。
- `ownerDocument`と`defaultView`を使用し、メイン文書固定のDOM参照を追加しない。
- 並べ替えモード終了またはコンポーネント破棄時は、キーボード状態、通知内容、視覚表現および一時DOMを解除する。
- iframe・非iframeで異なるキー操作や通知文を定義しない。

## 12. 確認観点

| 観点 | 確認内容 |
|---|---|
| 案内 | 並べ替えモード内の案内だけで必要な操作キーを確認できる。 |
| ハンドル | 対象行、操作内容、利用不能状態および案内との関連を支援技術で確認できる。 |
| 開始・移動 | キーボードだけで開始し、開始直後を含め矢印キー一回につき一行分だけ候補が変わる。3行目開始時の最初の上操作は2行目、最初の下操作は4行目になる。 |
| 確定・キャンセル | 確定時だけ一回更新し、キャンセルではデータとUndo履歴を変更しない。 |
| 制約 | ポインターDnDと同じ`rowspan`制約を適用し、禁止位置を飛び越えない。 |
| 通知 | 開始、位置変更、完了、キャンセルおよび禁止理由を必要な場面だけ通知する。 |
| フォーカス | 確定後とキャンセル後は対象行のハンドルへフォーカスがあり、明示的なモード終了後だけ切替ボタンへ戻る。セル編集、選択解除、別ブロック選択または削除では移動済みのフォーカスを奪わない。 |
| 編集環境 | iframe・非iframeで同じ操作、通知、視覚表現およびフォーカス管理になる。 |
| 影響範囲 | Table以外と操作対象外のTableへ追加イベントや状態を持ち込まない。 |
