## 2. 目的と責務

本書は、Table Reorder のアクセシビリティ要件を、利用者がどのような操作・状態・情報提供によって満たすかという観点から定義する。

通常の PC・タッチ操作、移動先、確定・キャンセル、結合セルを含む移動可否、データ保持、Undo、対象範囲、通常操作中のスクロールは `table-reorder-design.md` を正とし、本書では重複して定義しない。

本書では主に次を扱う。

- キーボードで行の並べ替え操作へ入る方法。
- キーボードでの開始、移動、確定、キャンセル。
- 操作前・操作中・操作後のフォーカス。
- フォーカスの視認性と遮蔽防止。
- ポインター操作 UI の操作しやすい大きさ。
- 初回の機能発見を補助する案内。
- 操作中のアクセシビリティ上必要な案内。
- 操作対象を識別するための情報。
- 操作状態、結果、移動できない理由の支援技術への情報提供。

本書のキーボード操作に関する設計は、hover 可能な環境でキーボードを利用する場合を対象とする。

プログラム内部の構造や実装方法は本書の対象としない。

## 3. 設計原則

1. キーボードだけで、行の並べ替え操作への到達から確定またはキャンセルまで完了できるようにする。
2. 通常操作で定義された移動可否と確定結果を、キーボード操作とドラッグを必要としない単一ポインター操作でも共通にする。
3. Table を選択しただけでは原則として Table Reorder のためにフォーカスを移動せず、WordPress エディター本来の操作文脈を維持する。ただし、キーボード向け初回案内を表示する場合は、案内対象と実フォーカスを一致させるためツールバーの「行を並べ替え」へフォーカスを移す。
4. 操作中は対象行を見失わないようにし、確定後・キャンセル後も次の操作を継続できる位置へ操作文脈を保つ。
5. フォーカス中の操作対象は、ポインターの hover に依存せず視覚的に確認できるようにする。
6. Table Reorder 自身の案内によって、フォーカス中の操作対象を完全に隠さない。
7. 操作案内は外部マニュアルを前提とせず確認できるようにし、操作状態に応じて必要な情報だけを示す。
8. 支援技術への情報提供は、対象、状態、結果、移動できない理由を理解するために必要な内容に絞り、不要な重複を避ける。
9. iframe・non-iframe の違いによって、利用者向けの操作、フォーカス、案内、支援技術への情報の意味を変えない。

## 4. 行の並べ替え操作へのアクセス

移動可能な各本文行には、その行を並べ替えるための操作 UI を対応付ける。

この操作 UI は次を満たす。

- キーボードだけで到達できる。
- 対象行を識別できる名前を持つ。
- 操作可能な UI であることを支援技術から判別できる。
- 利用者が判断する必要がある操作状態を支援技術から確認できる。
- キーボードフォーカスを視覚的に確認できる。
- hover だけを表示・到達の唯一の条件にしない。

移動できない行には、移動可能な行と同じ並べ替え操作 UI を提供しない。

PC・タッチの通常の行ハンドル操作と、ドラッグを使わない移動先選択の通常フローは `table-reorder-design.md` に従う。本書では、それらの操作に必要なフォーカスと支援技術への情報提供だけを定義する。

## 5. キーボード操作

### 5.1 操作への入口

Table をキーボードで選択しただけでは、原則として Table Reorder は行の並べ替え操作 UI へフォーカスを移動しない。キーボード向け初回案内を表示する場合だけ、§10.1 に従ってツールバーの「行を並べ替え」へフォーカスを移す。

hover 可能な環境では、ブロックツールバーの「行を並べ替え」をキーボードで実行したとき、次の順序でフォーカス先を決める。

1. 現在操作中または編集中の本文行を特定でき、その行が移動可能な場合は、その行の並べ替え操作 UI へ移る。
2. 現在の本文行を特定できない場合は、先頭の移動可能な行の並べ替え操作 UI へ移る。
3. 現在の本文行が移動できない場合は、別の行へ自動的に移らず、ツールバーの「行を並べ替え」に留まって理由を伝える。
4. 移動可能な本文行が存在しない場合も、ツールバーの「行を並べ替え」に留まってそのことを伝える。

この入口を実行しただけでは行移動を開始しない。

### 5.2 待機中の移動

行の並べ替え操作 UI へ入った後は、通常の `Tab` / `Shift + Tab` で移動可能な各行へ表内の論理的な順序で移動できるようにする。

Table Reorder 独自の循環は設けず、先頭または末尾を越えた場合は WordPress エディターの通常のフォーカス順へ戻る。

待機中の行の並べ替え操作 UI で、修飾キーなしの `ArrowUp` / `ArrowDown` が押された場合は、Table Reorder がそのキー入力を抑止し、行間のフォーカス移動には使用しない。

`Shift` / `Ctrl` / `Alt` / `Meta` を伴う `ArrowUp` / `ArrowDown` は Table Reorder では抑止せず、WordPress エディターまたはブラウザ側の通常操作へ渡す。

### 5.3 並べ替えの開始・移動・確定・キャンセル

フォーカス中の行の並べ替え操作 UI では、次のキーを使用する。

- `Enter` または `Space`: 並べ替えを開始する。
- `ArrowUp`: 前にある次の有効な移動先へ進む。
- `ArrowDown`: 後ろにある次の有効な移動先へ進む。
- `Enter` または `Space`: 現在の移動先で確定する。
- `Escape`: キャンセルする。

`ArrowUp` / `ArrowDown` による移動先変更は、並べ替えを開始した後だけ行う。

移動先は通常操作基本設計で定義された有効な位置に限る。結合セルの途中など移動できない位置は候補にしない。

先頭・末尾など、それ以上進めない場合は移動先を変更せず、そのことを支援技術へ伝える。

### 5.4 並べ替え中のフォーカス

キーボード並べ替え中は、確定またはキャンセルするまで操作対象の行の並べ替え操作 UI にフォーカスを維持する。
- 確定後は、移動後の同じ行に対応する並べ替え操作 UI にフォーカスを保つ。
- キャンセル後は、操作開始時と同じ行の並べ替え操作 UI へ戻す。

これにより、行の位置が変わっても利用者が操作対象を見失わず、そのまま次の操作を継続できるようにする。

## 6. ドラッグを必要としない単一ポインター操作のフォーカス

操作フロー自体は `table-reorder-design.md` を正とする。

PC で行ハンドルをクリックして移動対象を選択した場合は、その対象行の並べ替え操作 UI をフォーカス対象とする。移動先を表示しただけでは、最初の移動先へ自動的にフォーカスを移さない。

- 移動を確定した後は、移動後の同じ行に対応する並べ替え操作 UI へフォーカスを移す。
- キャンセルした後は、操作開始時の対象行の並べ替え操作 UI へ戻す。

タッチでは、並べ替えモードへ入っただけでは特定の行へフォーカスを移したり、移動対象を決めたりしない。

## 7. フォーカスの可視性と遮蔽防止

### 7.1 フォーカス可視性

キーボードフォーカスを受けた行の並べ替え操作 UI は、hover 状態だけに依存せず視覚的に識別できるようにする。

キーボード並べ替え中は、「フォーカスされていること」と「並べ替え中であること」を利用者が区別できるようにする。

### 7.2 フォーカス遮蔽防止

キーボードフォーカスを受けた行の並べ替え操作 UI を、Table Reorder 自身が表示する案内や移動先表示によって完全に隠さない。

操作によって対象や移動先が表示領域の外へ進んだ場合は、利用者が現在位置と移動方向を見失わない範囲で表示を追従させる。

キーボード操作では、`ArrowUp` / `ArrowDown` によって移動先候補が実際に変わった場合だけ、必要な表示追従を行う。

## 8. ポインター操作 UI の操作しやすさ

行の並べ替え操作 UI と、ドラッグを必要としない操作で表示する移動先 UI は、PC・タッチの双方で原則として 24 × 24 CSS px 以上の操作領域を確保する。

操作領域が 24 × 24 CSS px 未満となる場合は、WCAG 2.2 2.5.8 Target Size (Minimum) の spacing 例外を満たす配置とする。

視覚上のアイコンや線が小さい場合でも上記の操作可能領域を確保し、隣接する操作対象を誤って選びやすい密集配置を避ける。

## 9. 画面上の操作案内

操作案内は、通常操作基本設計で定義された操作を利用者が確認できるようにするとともに、キーボード利用者の機能発見と操作継続を補助する。

表示形式、表示の開始・終了条件、現在の画面表示文言は次を正とする。

| 場面 | 表示形式 | 表示開始 | 表示終了 | 英語 | 日本語 |
|---|---|---|---|---|---|
| PC の行ハンドル | ツールチップ | 移動可能な行ハンドルをポインターで操作するとき | ハンドルから離れるか、別の操作状態へ移るとき | Drag to move, or click to choose a destination. | ドラッグで移動　クリックで移動先を選択 |
| キーボード待機中 | ツールチップ | 行の並べ替え操作 UI がキーボードフォーカスを受けたとき | フォーカスが外れるか、並べ替えを開始するとき | Enter / Space: start moving | Enter / Space: 移動開始 |
| キーボード並べ替え中 | 画面固定の操作中案内 | キーボードで並べ替えを開始したとき | 確定またはキャンセルしたとき | ↑↓ Move　Enter / Space Confirm　Esc Cancel | ↑↓ 移動　Enter / Space 決定　Esc キャンセル |
| PC の移動先選択中 | 画面固定の操作中案内 | PC で行ハンドルをクリックして移動対象を選択したとき | 移動先の確定またはキャンセルで選択を終了したとき | Click destination　Esc Cancel | 移動先をクリック　Esc キャンセル |
| タッチの並べ替えモード | 画面固定の操作中案内 | タッチで「行を並べ替え」を実行し、並べ替えモードへ入ったとき | モードを終了したとき。移動先選択中は専用案内へ切り替える | Handle: drag to move / tap to choose destination　Cell: tap to edit | ハンドル: ドラッグで移動 / タップで移動先選択　セル: タップで編集 |
| タッチの移動先選択中 | 画面固定の操作中案内 | タッチで行ハンドルをタップして移動対象を選択したとき | 移動先を確定するか、移動先選択を終了したとき | Tap destination | 移動先をタップ |
| 移動できない行 | 一時通知 | 移動できない行から「行を並べ替え」を実行したとき | 一時通知の終了時 | This row is in a row-spanning cell and can’t be moved. | この行は縦結合セル内のため移動できません。 |
| 移動可能な行がない | 一時通知 | 移動可能な行がない Table で並べ替え操作へ入ろうとしたとき | 一時通知の終了時 | No rows can be reordered. | 並べ替えできる行がありません。 |

待機中の `Tab / Shift+Tab` による行選択は常時表示する操作案内には含めず、キーボード利用時の初回案内で一度だけ伝える。待機中ツールチップの `Enter / Space: start moving` は変更しない。

操作状態が変わった場合は、前の状態の案内を残したまま重ねず、新しい状態に必要な案内へ切り替える。

画面固定の操作中案内は、対象 Table が表示領域から完全に外れた場合は一時的に隠し、Table が表示領域へ戻った場合は再表示する。

## 10. 初回案内

初回案内の役割は、Table Reorder の存在とツールバーの「行を並べ替え」が入口であることを知らせ、キーボード利用時は待機中の行選択方法を必要最小限に伝える機能発見の補助に限定する。

初回案内は、ツールバーの「行を並べ替え」に関連付けた Popover 形式で表示する。キーボード向け初回案内では入口と実フォーカスを一致させるため「行を並べ替え」へフォーカスを移し、タッチ向け初回案内ではフォーカスを移動しない。

### 10.1 hover 可能な環境でのキーボード

hover 可能な環境では、キーボード操作で対象 Table を選択した初回に、ツールバーの「行を並べ替え」に関連付けて次の案内を表示する。

- English: `Reorder rows with the keyboard. Select “Reorder rows” in the toolbar, then use Tab / Shift+Tab to choose a row to reorder.`
- 日本語: `キーボードで行を並べ替えられます。ツールバーの「行を並べ替え」を選択し、Tab / Shift+Tab で並べ替える行を選べます。`

案内の表示と同時にツールバーの「行を並べ替え」へフォーカスを移す。追加の強調表示は行わず、実フォーカスの表示を利用する。これにより、案内表示直後に `Enter` を押すと、そのまま行の並べ替え操作 UI へ入れる。

利用者が案内を閉じた場合、または「行を並べ替え」を実行して行の並べ替え操作へ入った場合に表示を終了する。

一度表示を終了した後は自動再表示しない。

PC の通常のポインター操作には初回案内を追加しない。

### 10.2 タッチ

タッチでは、対象 Table を選択した初回かつ並べ替えモード開始前に、ツールバーの「行を並べ替え」に関連付けて次の案内を表示する。

- English: `Tap “Reorder rows” in the toolbar to begin.`
- 日本語: `ツールバーの「行を並べ替え」をタップして開始`

利用者が案内を閉じた場合、または「行を並べ替え」を実行して並べ替えモードへ入った場合に表示を終了する。

一度表示を終了した後は自動再表示せず、並べ替えモードへ入った後は通常の操作案内へ切り替える。

hover 可能な環境でのキーボードとタッチの初回案内は、それぞれ独立して扱う。

## 11. 操作 UI の識別情報

行の並べ替え操作 UI は、現在位置と行内容の短い代表情報を組み合わせ、同じ内容を持つ行でも対象を区別できるようにする。

空行は「Empty row」／「空の行」として識別する。

利用者へ提供する主な名前・説明は次のとおりとする。

| 対象 | 英語 | 日本語 |
|---|---|---|
| 行の並べ替え操作 | Reorder row %1$d: %2$s | %1$d行目「%2$s」を並べ替え |
| PC での行操作の説明 | Drag to move this row, or activate to choose a destination. | ドラッグして行を移動できます。実行すると移動先を選択できます。 |
| キーボードでの行操作の説明 | Press Enter or Space to start moving this row. | EnterまたはSpaceキーで、この行の移動を開始します。 |
| 行の前の移動先 | Move before row %1$d: %2$s | %1$d行目「%2$s」の前へ移動 |
| Table 末尾の移動先 | Move to the end of the table. | 表の末尾へ移動 |
| キャンセル | Cancel | キャンセル |
| 案内を閉じる | Close guidance | 案内を閉じる |
| ツールバー入口 | Reorder rows | 行を並べ替え |
| ツールバー入口の説明 | Move table rows using drag and drop, the keyboard, or destination selection. | ドラッグ、キーボード、または移動先の選択で表の行を移動します。 |

並べ替え後は現在位置を使って対象行の名前を更新する。

## 12. 支援技術への情報提供

支援技術へは、操作対象、操作状態、移動先、結果、移動できない理由を必要な場面で伝える。
### 12.1 並べ替え開始

キーボードで並べ替えを開始したとき、対象行の代表情報、現在位置、総行数を伝える。

- English: `Moving %1$s, row %2$d of %3$d.`
- 日本語: `%1$s、全%3$d行中%2$d行目の移動を開始しました。`

### 12.2 移動先選択の開始

ドラッグを必要としない操作で対象行を選択したとき、対象行と次に必要な操作を伝える。

- English: `%1$s selected. Choose a destination.`
- 日本語: `%1$sを選択しました。移動先を選んでください。`

### 12.3 キーボードでの移動先変更

有効な移動先が実際に変わったときだけ、対象行、移動先、総行数を伝える。

- English: `Move %1$s to position %2$d of %3$d.`
- 日本語: `%1$sを全%3$d行中%2$d行目へ移動します。`

### 12.4 移動確定

有効な別位置への移動が確定したとき、対象行、移動元、移動先を伝える。

- English: `Moved %1$s from position %2$d to %3$d.`
- 日本語: `%1$sを%2$d行目から%3$d行目へ移動しました。`

同じ位置の確定では移動結果として通知しない。

### 12.5 キャンセル

行順を変更せず操作を終了したとき、対象行と維持された位置を伝える。

- English: `Canceled moving %1$s. It remains at position %2$d.`
- 日本語: `%1$sの移動をキャンセルしました。位置は%2$d行目のままです。`

### 12.6 移動できない方向

先頭・末尾などで移動先候補が変わらない場合は、対象行と移動できない方向を伝える。同じ内容を必要以上に連続して繰り返さない。

- English: `%1$s cannot move any farther %2$s.`
- 日本語: `%1$sは、これ以上%2$sへ移動できません。`

### 12.7 結合セルによる移動不可

結合セルの制約によって対象行を移動できない場合は、対象行と理由を伝える。

- English: `%1$s cannot be moved because it is within a cell that spans multiple rows.`
- 日本語: `%1$sは、複数行にまたがる結合セルの範囲内にあるため移動できません。`

### 12.8 移動可能な行がない場合

移動可能な本文行がない場合は、そのことを伝える。

- English: `There are no rows that can be reordered in this table.`
- 日本語: `この表には並べ替えできる行がありません。`

## 13. 通常操作基本設計との関係

次の内容は `table-reorder-design.md` を正とし、本書では再定義しない。

- PC での行ハンドルの表示とドラッグ操作。
- タッチ端末での行並べ替えモードとハンドル操作。
- PC・タッチでドラッグを使わず移動先を選ぶ通常フロー。
- 移動先の表示。
- 確定とキャンセルの通常フロー。
- 結合セルを含む移動可否。
- データ保持と Undo。
- 対象範囲。
- 通常操作中のスクロール。

本書は、これらの通常操作にアクセシビリティ上必要なフォーカス、操作しやすさ、案内、識別情報、支援技術への情報提供を追加する。

## 14. iframe・non-iframe

iframe・non-iframe の両方で、次を同じ意味で成立させる。

- Table 選択だけでは原則として Table Reorder のためにフォーカスを移動しない。キーボード向け初回案内を表示する場合だけ、ツールバーの「行を並べ替え」へフォーカスを移す。
- ツールバーの「行を並べ替え」からキーボードで行の並べ替え操作へ入れる。
- キーボードの開始、移動、確定、キャンセルが同じである。
- フォーカスの維持・復元と視認性が同じである。
- 初回案内と操作中案内の意味が同じである。
- 操作対象、状態、結果、移動できない理由を支援技術から同じ意味で確認できる。

編集環境の違いを利用者が意識して操作方法を変える必要はない。
