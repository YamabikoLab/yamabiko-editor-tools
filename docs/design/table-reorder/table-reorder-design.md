## 2. 目的と責務

本書は、Table Reorder の基本要件を、利用者がどのような画面と操作で実現するかという観点から定義する。

主に次を扱う。

- PC での行ハンドルの見つけ方とドラッグ操作。
- タッチ端末での行並べ替え操作への切り替え。
- PC・タッチでドラッグを使わず移動先を選択する操作。
- 移動先の見せ方。
- 確定とキャンセルの流れ。
- 移動できない行・位置の扱い。
- 操作中の案内とスクロール。
- iframe・non-iframe で同じ意味の操作を維持すること。

キーボード操作、フォーカス、支援技術への情報提供など、アクセシビリティ固有の設計はアクセシビリティ基本設計で扱う。

プログラム内部の構造、ファイル名、関数名、DOM、イベント処理、ライブラリ設定、CSS などの実装方法は本書の対象としない。

## 3. 設計原則

1. 通常の Table 編集を妨げず、利用者が行を並べ替えようとしたときだけ並べ替え操作を提供する。
2. PC とタッチでは、それぞれの入力方法に適した入口を提供しつつ、移動できる行・移動先・確定結果は共通とする。
3. 行そのものではなく行ハンドルをドラッグ操作の入口とし、セルの選択や編集と行移動を区別する。
4. 有効な別位置への移動を確定した場合だけ行順を変更する。
5. キャンセル、同じ位置への操作、移動できない位置への操作では行順を変更しない。
6. 複数行にまたがる結合セルを壊す移動は提供しない。
7. iframe・non-iframe の違いによって、利用者向けの操作方法や結果を変えない。
8. 本文行は同じ本文領域内だけで移動し、ヘッダー・本文・フッターをまたぐ移動は提供しない。
9. 対応する Table ブロック以外には行並べ替え操作を提供せず、その編集に影響を与えない。

## 4. PC の通常操作

### 4.1 行ハンドル

PC では、移動可能な本文行へポインターを合わせると、その行の左端に行ハンドルを表示する。

- 行ハンドルは、どの行を動かすかを利用者が判断できる位置に表示する。
- 行そのものをドラッグ開始領域にはしない。
- セルを選択・編集する通常操作は維持する。
- 複数行にまたがる結合セルの範囲内など、移動できない行には移動可能な行と同じハンドルを提供しない。

### 4.2 ドラッグによる移動

PC では次の流れで行を並べ替える。

1. 移動したい行へポインターを合わせ、行ハンドルを表示する。
2. 行ハンドルをドラッグして移動を開始する。
3. ドラッグ中は、現在の有効な挿入位置を移動先として表示する。
4. 有効な別位置でドラッグを終了した場合、その位置への移動を確定する。
5. 無効な位置または元と同じ位置で終了した場合、行順を変更しない。

ドラッグ中に移動先を探すためのスクロールを利用できるようにする。

## 5. タッチ端末の通常操作

### 5.1 行並べ替え操作への切り替え

タッチ端末では、Table を選択したときにブロックツールバーから「行を並べ替え」を選択し、行並べ替え操作へ切り替える。

切り替え後は、移動可能な本文行に行ハンドルを表示する。

- セルのタップは通常のセル編集として扱う。
- 行ハンドルの操作だけを行並べ替えの入口とする。
- 通常の画面スクロールを不必要に妨げない。
- 「行を並べ替え」を終了した場合は、進行中の未確定操作を行順を変更せず終了する。

### 5.2 ドラッグによる移動

タッチ端末では、表示された行ハンドルをドラッグして行を並べ替える。

1. 移動したい行のハンドルをドラッグして移動を開始する。
2. ドラッグ中は、現在の有効な挿入位置を移動先として表示する。
3. 有効な別位置でドラッグを終了した場合、その位置への移動を確定する。
4. 無効な位置または元と同じ位置で終了した場合、行順を変更しない。

行そのものの長押しは、行移動の開始操作にはしない。

## 6. ドラッグを使わない移動先選択

PC・タッチともに、行ハンドルからドラッグせず移動先を選ぶ操作を利用できる。

### 6.1 PC

1. 移動したい行へポインターを合わせ、行ハンドルを表示する。
2. 行ハンドルをクリックし、その行を移動対象として選択する。
3. Table 内に、その行を挿入できる有効な移動先を表示する。
4. 移動先をクリックすると、その位置への移動を確定する。
5. キャンセルした場合は、行順を変更せず移動先選択を終了する。

行ハンドルをドラッグした場合はドラッグ操作として扱い、その後に同じ操作をクリックとして重ねて扱わない。

### 6.2 タッチ

1. 「行を並べ替え」中に、移動したい行のハンドルをタップする。
2. Table 内に、その行を挿入できる有効な移動先を表示する。
3. 移動先をタップすると、その位置への移動を確定する。
4. キャンセルした場合は、行順を変更せず移動先選択を終了し、「行を並べ替え」に戻る。

移動先を探している間も縦スクロールを利用できるようにし、スクロール操作だけで移動を確定しない。

## 7. 移動先の表示と確定

移動先は、利用者が「どの行の前後へ入るか」を判断できる行間の位置として示す。

- ドラッグ中は、現在の挿入位置を視覚的に示す。
- ドラッグを使わない操作では、選択できる有効な移動先を示す。
- 元と同じ位置は確定対象にしない。
- 複数行にまたがる結合セルの途中は移動先にしない。
- 有効な別位置への移動を確定したときだけ Table の行順を更新する。
- 移動後もセル内容、セル属性、装飾を保持し、行の位置だけを変更する。
- 一回の確定した行移動は、一回の Undo で戻せる操作として扱う。

## 8. 結合セルを含む Table

### 8.1 複数行にまたがる結合セル

複数行にまたがる結合セルの構造を壊さないよう、利用者には次の制約として示す。

- 結合範囲内の行そのものは移動対象にしない。
- 結合範囲の途中は移動先にしない。
- 結合範囲外の行は、結合範囲全体を越えた前後の有効な位置へ移動できる。
- 移動できない行や位置を、有効な移動対象・移動先と同じ見せ方にはしない。

### 8.2 複数列にまたがる結合セル

複数列にまたがる結合セルだけを含む行は、安全に行単位で移動できる場合は通常の移動可能な行として扱う。

## 9. 操作案内とスクロール

行並べ替えを利用している場面では、現在利用できる操作を判断できる短い案内を表示する。

- PC の行ハンドルでは、ドラッグまたは移動先選択を利用できることを示す。
- タッチの「行を並べ替え」中は、行ハンドルのドラッグ・タップとセル編集の違いを示す。
- 移動先選択中は、移動先を選択できることとキャンセルできることを示す。
- 移動できない行を操作しようとした場合は、必要に応じて移動できないことを利用者へ示す。

タッチの「行を並べ替え」中とタッチの移動先選択中では、画面固定の操作案内を次のように表示する。

- 初期表示は viewport 上側とする。
- 上方向へスワイプした場合は viewport 上側へ表示する。
- 下方向へスワイプした場合は viewport 下側へ表示する。
- スワイプ終了後も直前の表示側を維持し、反対方向のスワイプを検出したときに反対側へ切り替える。
- 操作案内の表示位置を切り替えても、通常のスクロールや移動先探索を妨げない。

操作案内や移動先の表示によって、移動先を探すための通常のスクロールを妨げない。

具体的な案内文、フォーカス、支援技術への通知はアクセシビリティ基本設計と利用者向けメッセージの管理に委ねる。

## 10. iframe・non-iframe

Table Reorder は iframe・non-iframe の両方で、利用者から見て同じ意味の操作を提供する。

- PC の行ハンドル表示とドラッグ操作。
- タッチの「行を並べ替え」への切り替えとハンドル操作。
- ドラッグを使わない移動先選択。
- 移動可能・移動不能の扱い。
- 移動先の表示。
- 確定、キャンセル、Undo。
- 操作中のスクロール。

編集環境の違いを利用者が意識して操作方法を変える必要はない。

## 11. アクセシビリティ基本設計との分離

本書は通常操作の利用者向け How を定義する。

次はアクセシビリティ基本設計で扱い、本書では重複して定義しない。

- キーボードだけで行並べ替えへ到達し完了する手順。
- キーボード操作中の移動、確定、キャンセル。
- フォーカスの可視性と操作前後のフォーカス位置。
- 初回案内の表示条件。
- 操作対象、状態、結果、移動できない理由の支援技術への情報提供。
- 操作 UI のアクセシブルな名前、役割、状態。
- ポインター操作 UI のアクセシビリティ上必要な操作領域。

通常操作とアクセシビリティ操作は、基本要件で定義された移動可否、データ保持、確定、キャンセル、Undo、結合セル制約を共有する。

## 12. 完了条件

- PC で行ハンドルを見つけ、ドラッグして移動する流れを説明できる。
- タッチ端末で行並べ替えへ切り替え、行ハンドルをドラッグして移動する流れを説明できる。
- PC・タッチでドラッグを使わず移動先を選ぶ流れを説明できる。
- 移動先、確定、キャンセル、移動不能の見せ方を説明できる。
- 複数行にまたがる結合セルの制約が利用者の操作上どのように現れるかを説明できる。
- 操作案内とスクロールの扱いを説明できる。
- タッチの操作案内が上下スワイプ方向に応じて viewport 上側・下側へ切り替わり、反対方向のスワイプまで直前の表示側を維持する挙動を説明できる。
- iframe・non-iframe で利用者体験を変えない方針を説明できる。
- 基本要件の主要項目について利用者視点の How を追跡できる。
- プログラム内部の構造や実装方法を記載していない。
