# Table Reorder アクセシビリティ要件定義書

## 1. 文書情報

| 項目 | 内容 |
|---|---|
| 機能名 | Table Reorder アクセシビリティ拡張 |
| 対象 | WordPress Gutenberg のコア Tableブロック |
| 文書種別 | 要件定義書 |
| 関連Issue | #104 |
| 基礎要件 | `table-reorder-requirements.md` |

## 2. 目的と責務

本書は、既存のTable Reorderを、外部マニュアルを読まなくてもポインターまたはキーボードで理解して操作できるようにするためのアクセシビリティ要件を定める。

既存のTable Reorder要件定義書を基礎とし、本書では次だけを追加で扱う。

- キーボードによる行の並べ替え
- 並べ替えモード内の短い操作案内
- ドラッグハンドルのラベルと利用不能状態
- スクリーンリーダーへの必要最小限の通知
- 操作後のフォーカス維持と、明示的なモード終了時の復元

行データの保持、Undo、`rowspan`制約、対象範囲、保存形式およびポインターDnDの要件は、既存のTable Reorder要件定義書を正とし、本書では重複して定義しない。

## 3. 対象範囲

- コアTableブロックの`tbody`内の本文行を対象とする。
- 既存のドラッグハンドルを、ポインター操作とキーボード操作の共通の開始点とする。
- キーボードだけで、開始、上下移動、確定、キャンセルを完了できるようにする。
- 並べ替えモード中に、ポインター操作とキーボード操作の短い案内を画面上で確認できるようにする。
- スクリーンリーダー利用者が、対象行、現在位置、操作結果および移動できない理由を必要な場面で確認できるようにする。
- iframe・非iframeの編集環境で同じ要件を満たす。

## 4. 操作の流れ

1. Tableブロックを選択する。
2. ブロックツールバーの「行を並べ替え」を押す。
3. 画面上の短い操作案内を確認する。
4. 移動する行のドラッグハンドルへフォーカスする。
5. `Enter`または`Space`でキーボード並べ替えを開始する。
6. `ArrowUp`または`ArrowDown`で移動先を一行ずつ変更する。
7. `Enter`または`Space`で確定するか、`Escape`でキャンセルする。
8. 必要に応じて「並べ替えを終了」を押して通常編集へ戻る。

## 5. 機能要件

| ID | 項目 | 要件 |
|---|---|---|
| A11Y-FR-01 | 共通ハンドル | 既存のドラッグハンドルから、ポインターDnDとキーボード並べ替えのどちらも開始できる。 |
| A11Y-FR-02 | 画面上の案内 | 並べ替えモード中に、ポインター操作とキーボード操作を説明する短い案内を表示する。 |
| A11Y-FR-03 | ハンドルの識別 | 各ハンドルに、対象行と並べ替え操作であることが分かるアクセシブルな名前を付ける。 |
| A11Y-FR-04 | キーボード操作 | `Enter`または`Space`、`ArrowUp`、`ArrowDown`、`Escape`だけで開始、移動、確定、キャンセルを行える。 |
| A11Y-FR-05 | 一行単位の移動 | 開始位置から最初に押す場合を含め、矢印キーを一回押すごとに、移動先候補を一行分だけ上または下へ変更する。 |

| A11Y-FR-09 | 編集環境 | iframe・非iframeのどちらでも、案内、キーボード操作、通知およびフォーカス管理を同じように提供する。 |

## 6. 詳細要件

### 6.1 キー操作

| 状態 | キー | 動作 |
|---|---|---|
| 待機中 | `Enter`または`Space` | フォーカス中の行の並べ替えを開始する。 |
| 操作中 | `ArrowUp` | 移動先候補を一行分上へ変更する。 |
| 操作中 | `ArrowDown` | 移動先候補を一行分下へ変更する。 |
| 操作中 | `Enter`または`Space` | 現在の有効な移動先へ確定する。 |
| 操作中 | `Escape` | 変更を確定せず、開始前の順序へ戻す。 |

開始時と確定時に使用するキーは同じとし、別のショートカットを追加しない。

例えば3行目で開始した場合、最初の`ArrowUp`で2行目が候補になり、最初の`ArrowDown`で4行目が候補になる。開始直後の最初の矢印キーが同じ位置を指す状態にはしない。

### 6.2 画面上の案内

- 案内は並べ替えモード中だけ表示する。
- 外部マニュアルへの参照を前提とせず、操作に必要なキーを案内内へ明記する。
- ポインター操作とキーボード操作を一つの短い案内にまとめる。
- 複数段階のチュートリアルや初回だけのガイドは追加しない。
- 案内は各ハンドルから参照できる説明としても利用できるようにする。

案内文は、次の内容を簡潔に伝える。

> ハンドルをドラッグして移動できます。キーボードでは Enter または Space で開始し、上下矢印で移動、Enter または Space で確定、Escape でキャンセルします。

### 6.3 ドラッグハンドル

- ハンドルはキーボードでフォーカスできる。
- アクセシブルな名前には本文行の現在位置を含める。
- 移動できない行は利用不能であることを支援技術へ伝える。
- 移動できない行でも理由を確認できるようにし、開始操作を試みた場合は理由を通知する。
- アイコンの見た目だけに操作内容を依存しない。

ラベルは、次の形式を基準とする。

> 3行目を並べ替える

### 6.4 スクリーンリーダー通知

通知は、利用者の判断に必要な次の場面に限定する。

- 並べ替えを開始したとき
- 有効な移動先が変わったとき
- 移動を確定したとき
- 移動をキャンセルしたとき
- 先頭、末尾または`rowspan`制約により移動できないとき

通知には、可能な範囲で現在位置と全行数を含める。

同じ移動先や同じ禁止理由が変わっていない間は、同じ通知を繰り返さない。ポインターDnDとキーボード操作から同じ内容が重複して読み上げられないようにする。

### 6.5 フォーカス管理

- キーボード並べ替えの開始時は、フォーカス中のハンドルを操作対象として維持する。
- 確定後は、移動後の位置にある同じ行のハンドルへフォーカスを維持する。
- キャンセル後は、開始前の位置にある同じ行のハンドルへフォーカスを戻す。
- 利用者がブロックツールバーの「並べ替えを終了」を明示的に操作した場合だけ、通常表示へ切り替わったモード切替ボタンへフォーカスを戻す。
- セル編集への復帰、Tableブロックの選択解除、別ブロックの選択またはTableブロックの削除によって並べ替えモードが終了した場合は、既に移動したフォーカスを尊重し、モード切替ボタンへの復元を行わない。
- 明示的な終了時でも復元先が存在しない場合は、例外を発生させずフォーカス処理を省略する。

### 6.6 移動できない操作

- 先頭行からさらに上、末尾行からさらに下へは移動しない。
- `rowspan`制約により禁止される位置へは移動先候補を変更しない。
- 禁止操作では表データとUndo履歴を変更しない。
- `rowspan`による禁止理由は、既存要件と同じ内容を画面通知およびスクリーンリーダー通知へ使用する。
- 禁止位置を飛び越えて別の位置へ自動移動しない。

## 7. 対象外

- 上下移動専用ボタン
- 左右キー、`Home`、`End`、`PageUp`、`PageDown`による移動
- ショートカットキーのカスタマイズ
- 複数行の選択や同時移動
- 複雑なチュートリアルや初回ガイド
- 汎用アクセシビリティ基盤の新設
- ポインター操作と異なる独自の並べ替え仕様
- 列、`thead`および`tfoot`の並べ替え

## 8. 完了条件

- 並べ替えモード内の案内だけで、ポインター操作とキーボード操作の方法を理解できる。
- 各ドラッグハンドルの対象行と操作内容を、画面表示に依存せず確認できる。
- キーボードだけで開始、上下移動、確定およびキャンセルを完了できる。
- 開始位置から最初に押す場合を含め、一回の矢印キー操作で移動先候補が一行分だけ変わる。
- キーボード操作でも、セル内容、セル属性、装飾、Undoおよび`rowspan`制約が既存のポインターDnDと同じように維持される。
- 操作開始、移動先、完了、キャンセルおよび移動できない理由が、必要な場面だけ通知される。
- 確定後とキャンセル後に対象行のハンドルへフォーカスがあり、明示的なモード終了後だけモード切替ボタンへ復元される。セル編集、選択解除、別ブロック選択またはブロック削除による終了では移動済みのフォーカスを奪わない。
- iframe・非iframeの両方で同じ要件を満たす。
- Table以外のブロックおよび並べ替え操作の対象ではないTableブロックへ影響を与えない。
