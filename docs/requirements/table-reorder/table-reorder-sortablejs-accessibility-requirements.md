# Table Reorder アクセシビリティ要件定義書

## 1. 文書情報

| 項目 | 内容 |
|---|---|
| 機能名 | Table Reorder アクセシビリティ |
| 対象 | WordPress Core Table と Flexible Table Block |
| 文書種別 | アクセシビリティ要件定義書 |
| 基礎要件 | `table-reorder-sortablejs-requirements.md` |

## 2. 目的と責務

本書は Table Reorder について、利用者が何をできる必要があるか、どのアクセシビリティ上の性質を追加で満たす必要があるかを定義する。

通常の PC・タッチ操作、データ保持、Undo、結合セルの基本的な移動制約、対象範囲などは `table-reorder-sortablejs-requirements.md` を正とし、本書では重複して定義しない。

具体的なキー割り当て、画面構成、操作フロー、状態遷移、フォーカス遷移、案内の表示条件・文言、支援技術への情報提供方法など、利用者向けの具体的な実現方法は基本設計で扱う。

プログラム内部の構造や実装方法は本書の対象としない。

## 3. アクセシビリティ参照基準

Table Reorder が追加・変更する UI について、**WCAG 2.2 Level AA** をアクセシビリティ要件の参照基準とする。

対象は Table Reorder が追加・変更する UI の範囲に限定し、プラグイン全体や WordPress エディター全体の WCAG 適合を宣言するものではない。

本書では、特に以下の達成基準を要件整理の判断材料とする。

- 2.4.11 Focus Not Obscured (Minimum)
- 2.5.7 Dragging Movements
- 2.5.8 Target Size (Minimum)
- 4.1.2 Name, Role, Value

具体的な画面構成、操作手順、寸法、配置、フォーカス遷移、案内、支援技術への情報提供方法は基本設計で定義する。

## 4. 対象範囲

- WordPress Core Table と Flexible Table Block の本文行を対象とする。
- iframe・non-iframe の両方で同じアクセシビリティ要件を満たす。
- 移動可能な行について、キーボードだけで並べ替えを完了できる。
- PC・タッチともに、ドラッグを必要としない単一ポインター操作だけで並べ替えを完了できる。
- 移動可能な各行の並べ替え操作へ、キーボードだけで論理的な順序で到達できる。
- 操作中・操作後に操作対象や操作文脈を見失わない。
- 必要な操作案内を画面上で確認できる。
- 操作対象、操作状態、操作結果、移動できない理由を支援技術から確認できる。
- 基本要件で定義された結合セルの制約、データ保持、Undo、対象範囲を、キーボード操作と単一ポインター操作にも適用する。

## 5. 共通要件

| ID | 項目 | 要件 |
|---|---|---|
| A11Y-FR-01 | キーボード完結 | 移動可能な行について、キーボードだけで並べ替えを開始し、移動先を選び、確定またはキャンセルまで完了できる。 |
| A11Y-FR-02 | 単一ポインター操作 | PC・タッチともに、ドラッグを必要としない単一ポインター操作だけで並べ替えを完了できる。 |
| A11Y-FR-03 | ターゲットサイズ | ポインターで操作する並べ替え UI は、細かく狙わなくても操作できる領域を確保し、WCAG 2.2 2.5.8 Target Size (Minimum) を満たす。 |
| A11Y-FR-04 | 論理的なアクセス順 | 移動可能な各行の並べ替え操作へ、キーボードだけで論理的な順序で到達できる。 |
| A11Y-FR-05 | 操作文脈 | キーボード操作中・操作後に、利用者が現在の操作対象や操作文脈を見失わない。 |
| A11Y-FR-06 | フォーカス可視性 | キーボードで操作対象になっている要素を視覚的に確認できる。 |
| A11Y-FR-07 | フォーカス遮蔽 | キーボードフォーカスを受けた並べ替え UI が、Table Reorder 自身の表示によって完全に隠れない。 |
| A11Y-FR-08 | 操作案内 | 外部マニュアルを前提とせず、必要な操作方法を画面上で確認できる。 |
| A11Y-FR-09 | 支援技術への情報提供 | 並べ替え対象、操作状態、操作結果、移動できない理由を支援技術から確認できる。 |
| A11Y-FR-10 | 名前・役割・状態 | 操作対象となる並べ替え UI について、名前・役割・状態を支援技術から判別でき、対象行と操作内容を識別できる。 |
| A11Y-FR-11 | 基本要件の共有 | 基本要件で定義された結合セルの制約、データ保持、Undo、対象範囲を、キーボード操作と単一ポインター操作にも適用する。 |
| A11Y-FR-12 | 編集環境 | iframe・non-iframe の両方で同じアクセシビリティ要件を満たす。 |

## 6. キーボード利用

- hover やポインター操作を利用しなくても、キーボードだけで行の並べ替え操作へ到達できる。
- キーボードだけで複数の移動可能な行へ論理的な順序で到達できる。
- キーボードだけで開始、移動先の選択、確定、キャンセルまで完了できる。
- 操作中・操作後に対象行や操作文脈を見失わない。
- キーボードフォーカスを受けた操作対象を視覚的に確認できる。
- Table Reorder 自身の表示によって、キーボードフォーカスを受けた操作対象が完全に隠れない。

具体的な操作入口、キー、フォーカス移動、フォーカス維持・復元の流れはアクセシビリティ基本設計で定義する。

## 7. ドラッグを必要としない単一ポインター操作

- PC・タッチともに、ドラッグを必要としない単一ポインター操作だけで行の並べ替えを完了できる。
- 単一ポインター操作でも、基本要件で定義された移動可能な行と有効な移動先だけを利用できる。
- 確定またはキャンセルまで一連の操作を完了できる。

具体的な操作入口、移動先の選択方法、確定・キャンセルの手順は基本設計で定義する。

## 8. 操作案内

- 外部マニュアルを読まなくても、必要な操作方法を画面上で確認できる。
- キーボード操作、ドラッグ操作、ドラッグを必要としない単一ポインター操作に必要な情報を確認できる。
- 操作中の状態を理解するために必要な案内を確認できる。

具体的な表示タイミング、表示方法、文言は基本設計で定義する。

## 9. フォーカス・操作文脈

- キーボード利用者が移動可能な行の並べ替え操作へ到達できる。
- 並べ替え中に意図せず操作対象を見失わない。
- キーボードフォーカスを受けた操作対象を視覚的に確認できる。
- キーボードフォーカスを受けた操作対象が Table Reorder 自身の表示によって完全に隠れない。
- 確定・キャンセルなどの操作後も、利用者が次の操作を継続できる位置に操作文脈が保たれる。

具体的なフォーカス移動順、フォーカス先、復元先、可視性を保つ方法はアクセシビリティ基本設計で定義する。

## 10. 支援技術への情報提供

- 行の並べ替え操作であることと、その対象行を識別できる。
- 操作 UI の名前・役割・状態を支援技術から確認できる。
- 現在の操作状態を把握できる。
- 移動結果を把握できる。
- 移動できない場合は、その理由を把握できる。
- 不要な重複した情報提供によって操作を妨げない。

具体的な属性、通知タイミング、通知文言、通知方法はアクセシビリティ基本設計または実装側で扱う。

## 11. 基本要件との整合

- 基本要件で定義された結合セルを含む移動可否を、キーボード操作とドラッグを必要としない単一ポインター操作にも同様に適用する。
- 基本要件上移動できない場合は、その理由を支援技術から確認できる。
- 基本要件で定義されたデータ保持、Undo、対象範囲、編集環境の要件をアクセシビリティ操作でも満たす。

結合セルの具体的な移動可否、データ保持、Undo、対象範囲の詳細は基本要件を正とし、本書では再定義しない。

## 12. 対象外

- 基本要件ですでに定義されている通常の PC・タッチ操作の再定義。
- データ保持、Undo、結合セルの基本的な移動制約の再定義。
- 具体的なキー割り当て。
- 具体的な画面構成、操作入口、操作フロー、状態遷移。
- ポインター操作 UI の具体的な寸法・配置。
- フォーカス順、フォーカス先、復元先、可視性確保方法の具体設計。
- 操作案内の具体的な表示条件、表示方法、文言。
- 支援技術への情報提供に用いる具体的な属性、通知タイミング、通知文言、通知方法。
- プログラム内部の構造や実装方法。
- Jest / Playwright テストの追加・変更。
- 並べ替えライブラリの選定や置き換え。
- 複数行の同時移動。
- 複雑なチュートリアル。

## 13. 完了条件

- 基本要件を基礎文書として参照している。
- WordPress Core Table と Flexible Table Block を対象としている。
- Table Reorder が追加・変更する UI について、WCAG 2.2 Level AA をアクセシビリティ要件の参照基準としている。
- 通常の PC・タッチ操作を本書で重複定義していない。
- キーボードだけで並べ替えを完了できる要件が定義されている。
- PC・タッチともに、ドラッグを必要としない単一ポインター操作で並べ替えを完了できる要件が定義されている。
- ポインターで操作する並べ替え UI について、WCAG 2.2 2.5.8 Target Size (Minimum) を満たす要件が定義されている。
- キーボードから移動可能な各行の並べ替え操作へ論理的な順序で到達できる要件が定義されている。
- 操作中・操作後に利用者が操作対象や文脈を見失わない要件が定義されている。
- キーボードフォーカスを受けた操作対象を視覚的に確認できる要件が定義されている。
- キーボードフォーカスを受けた操作対象が Table Reorder 自身の表示によって完全に隠れない要件が定義されている。
- 操作対象、状態、結果、移動不能理由を支援技術から確認できる要件が定義されている。
- 基本要件の結合セル制約、データ保持、Undo、対象範囲をキーボード操作・単一ポインター操作にも適用する要件が定義されている。
- iframe・non-iframe の両方を対象としている。
- 要件はアクセシビリティ上何を満たす必要があるかに留まり、具体的な操作手順や実装方法を含まない。
