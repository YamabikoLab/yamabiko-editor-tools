## 2. 目的と責務

本書は、SortableJS版Table Reorderについて、利用者が何をできる必要があるか、どのアクセシビリティ上の性質を満たす必要があるかを定義する。

通常のPC・タッチ操作、データ保持、Undo、`rowspan` / `colspan`の基本的な移動制約、対象範囲などは、`table-reorder-sortablejs-requirements.md`を正とし、本書では重複して定義しない。

具体的なキー割り当て、UI、操作フロー、状態遷移、フォーカス遷移、案内の表示条件・文言、ARIA属性、スクリーンリーダー通知のタイミング・方法など、**どのように実現するか**は #199 のアクセシビリティ基本設計または実装側で扱う。

## 3. アクセシビリティ参照基準

Table Reorderが追加・変更するUIについて、**WCAG 2.2 Level AA**をアクセシビリティ要件の参照基準とする。

対象はTable Reorderが追加・変更するUIの範囲に限定し、プラグイン全体やWordPressエディター全体のWCAG適合を宣言するものではない。

本書では、特に以下の達成基準を要件整理の判断材料とする。

- 2.4.11 Focus Not Obscured (Minimum)
- 2.5.7 Dragging Movements
- 2.5.8 Target Size (Minimum)
- 4.1.2 Name, Role, Value

具体的なUI寸法、配置、スクロール処理、ARIA属性、通知方法などは #199 または実装側で決定する。

## 4. 対象範囲

- コアTableブロックの`tbody`内の本文行を対象とする。
- iframe・non-iframeの両方で同じアクセシビリティ要件を満たす。
- 移動可能な行について、キーボードだけで並べ替えを完了できるようにする。
- PC・タッチともに、ドラッグを必要としない単一ポインター操作だけで並べ替えを完了できるようにする。
- 移動可能な各行の並べ替え操作へ、キーボードだけで論理的な順序でアクセスできるようにする。
- 操作対象、操作状態、操作結果、移動できない理由を支援技術から確認できるようにする。
- 基本要件で定義された`rowspan` / `colspan`の制約、データ保持、Undo、対象範囲を、キーボード操作と単一ポインター操作にも適用する。

## 6. PCのアクセシビリティ要件

PCの通常操作はSortableJS版基本要件を前提とし、本書ではアクセシビリティ上必要な追加要件だけを定義する。

- hover操作を利用できなくても、キーボードから行の並べ替え操作へアクセスできる。
- キーボードだけで複数の移動可能な行の並べ替え操作へ順序立ててアクセスできる。
- 必要な操作案内を画面上で確認できる。

## 7. タッチ端末のアクセシビリティ要件

タッチ端末の通常操作はSortableJS版基本要件を前提とし、本書ではアクセシビリティ上必要な追加要件だけを定義する。

- 並べ替え操作へ移行しても、利用者がそれまで操作していた行の文脈を失わない。
- 外付けキーボード等を利用する場合も、キーボードだけで行の並べ替えを完了できる。
- 必要な操作案内を画面上で確認できる。
- 必要な状態や操作結果を支援技術から確認できる。

## 8. 操作案内

- 外部マニュアルを読まなくても、画面上の短い案内から必要な操作方法を理解できる。
- キーボード操作、ドラッグ操作、ドラッグを必要としない単一ポインター操作に必要な情報を確認できる。

具体的な表示タイミング、表示方法、文言、操作UIとの関連付けは #199 で基本設計として整理する。

## 9. フォーカス・操作文脈

- キーボード利用者が移動可能な行の並べ替え操作へ到達できる。
- 並べ替え中に意図せず操作対象を見失わない。
- キーボードフォーカスを受けた並べ替えUIが、Table Reorderが生成するUIによって完全に隠れない。
- 確定・キャンセルなどの操作後も、利用者が次の操作を継続できる位置に操作文脈が保たれる。

具体的なフォーカス移動順、キー操作、フォーカス先、復元先、スクロールや配置による可視性確保の方法は #199 で基本設計として整理する。

## 10. 支援技術への情報提供

- 行の並べ替え操作UIの名前・役割・状態をプログラムから判別できる。
- 行の並べ替え操作であることと、その対象行を識別できる。
- 現在の操作状態を把握できる。
- 移動結果を把握できる。
- 移動できない場合は、その理由を把握できる。
- 不要な重複通知によって操作を妨げない。

具体的なARIA属性、通知タイミング、通知文言、通知方法は #199 で基本設計として整理する。

## 11. 結合セル・既存制約との整合

キーボード操作とドラッグを必要としない単一ポインター操作にも、SortableJS版基本要件の制約を同じように適用する。

特に`rowspan`について、以下を満たす。

- `rowspan`範囲内の行そのものは移動対象にしない。
- `rowspan`範囲の途中を移動先として確定しない。
- `rowspan`範囲外の移動可能な行は、縦結合範囲全体を越えた有効な位置へ前後に移動できる。
- 無効な操作ではTableの行順を変更しない。

`colspan`、データ保持、Undo、対象範囲などの詳細はSortableJS版基本要件を正とする。

- 具体的なUI・操作フロー・状態遷移の決定

- フォーカス順・フォーカス先・復元先・可視性確保方法の具体設計
- 操作案内の具体的な表示条件・表示方法・文言の決定
- ARIA属性の具体的な選定
- スクリーンリーダー通知のタイミング・文言・方法の具体設計

## 13. 完了条件

- `table-reorder-sortablejs-requirements.md`を基礎文書として参照している。
- Table Reorderが追加・変更するUIについて、WCAG 2.2 Level AAをアクセシビリティ要件の参照基準としている。
- 通常のPC・タッチ操作を本書で重複定義していない。
- キーボードだけで並べ替えを完了できる要件が定義されている。
- PC・タッチともに、ドラッグを必要としない単一ポインター操作で並べ替えを完了できる要件が定義されている。
- ポインターで操作する並べ替えUIについて、細かく狙わなくても普通に操作できる操作領域を確保し、WCAG 2.2 2.5.8 Target Size (Minimum)を満たす要件が定義されている。
- キーボードから移動可能な各行の並べ替え操作へ論理的な順序でアクセスできる要件が定義されている。
- 操作中・操作後に利用者が操作対象や文脈を見失わない要件が定義されている。
- キーボードフォーカスを受けた並べ替えUIが、Table Reorderが生成するUIによって完全に隠れない要件が定義されている。
- 操作UIの名前・役割・状態を支援技術からプログラム的に判別できる要件が定義されている。
- 操作対象・状態・結果・移動不能理由を支援技術から確認できる要件が定義されている。
- 基本要件の`rowspan` / `colspan`制約、データ保持、Undo、対象範囲をキーボード操作・単一ポインター操作にも適用する要件が定義されている。
- iframe・non-iframeの両方を対象としている。
- キー割り当て、具体UI、操作フロー、状態遷移、フォーカス遷移、案内表示方法、通知方法などを #199 へ分離している。
- 実装方法や基本設計へ踏み込まず、利用者から見えるアクセシビリティ要件として整理されている。
