# Table Reorder 要件定義書

## 1. 目的

WordPress Gutenberg の対応する Table ブロックについて、セル内容をコピーし直すことなく、本文行を安全に並べ替えられるようにする。

本書は Table Reorder が利用者に何を提供し、どの振る舞いと制約を満たす必要があるかを定義する。

具体的な画面構成、操作手順、表示方法、プログラム内部の実現方法は基本設計書または実装側で扱う。

キーボード操作、フォーカス、支援技術への情報提供など、アクセシビリティ上追加で満たす必要がある要件は別文書で定義する。

## 2. 対象範囲

- WordPress Core Table と Flexible Table Block の本文行を対象とする。
- 本文行は同じ本文領域内で並べ替える。
- ヘッダー、本文、フッターをまたぐ移動は行わない。
- 対応する Table ブロック以外へ影響を与えない。
- iframe・non-iframe の両方で同じ基本要件を満たす。

## 3. 共通要件

| ID | 項目 | 要件 |
|---|---|---|
| FR-01 | 行の並べ替え | 対応する Table ブロックの本文行を、同じ本文領域内の別の位置へ移動できる。 |
| FR-02 | 対象範囲 | ヘッダー、本文、フッターをまたぐ移動を行わない。 |
| FR-03 | データ保持 | 移動後もセル内容、セル属性、装飾を保持する。 |
| FR-04 | Undo | 一回の行移動を一回の Undo 操作として元に戻せる。 |
| FR-05 | 確定 | 有効な別位置への移動を確定した場合だけ Table の行順を更新する。 |
| FR-06 | 無効操作 | キャンセルまたは無効な移動では Table のデータを変更しない。 |
| FR-07 | 編集環境 | iframe・non-iframe の両方で同じ基本要件を満たす。 |
| FR-08 | 影響範囲 | 対応する Table ブロック以外へ影響を与えない。 |

## 4. PC・タッチ操作

| ID | 項目 | 要件 |
|---|---|---|
| INPUT-01 | PC ポインター操作 | PC では、移動可能な本文行をポインターのドラッグ操作で並べ替えられる。 |
| INPUT-02 | PC の通常編集 | 行の並べ替え操作を利用していないときは、通常の Table 編集を妨げない。 |
| INPUT-03 | タッチ操作 | タッチ端末では、移動可能な本文行をタッチによるドラッグ操作で並べ替えられる。 |
| INPUT-04 | タッチの通常編集 | セルの通常操作を Table 編集として利用でき、行の並べ替えが意図せず開始されない。 |
| INPUT-05 | 通常スクロール | タッチ端末で Table や編集画面の通常スクロールを妨げない。 |

PC・タッチでどの画面や操作入口を利用し、どのような手順で並べ替えるかは通常操作の基本設計で定義する。

ドラッグを必要としない単一ポインター操作など、アクセシビリティ上追加で必要な操作方法はアクセシビリティ要件で定義する。

## 5. 結合セルの保護

### 5.1 複数行にまたがる結合セル

- 複数行にまたがる結合範囲内の行そのものは移動できない。
- 複数行にまたがる結合範囲の途中へ別の行を挿入できない。
- 結合範囲外の行は、結合範囲全体を越えて前後へ移動できる。
- 結合範囲を越える場合でも、結合範囲の途中を移動先として確定しない。
- 禁止された操作では Table のデータを変更しない。

### 5.2 複数列にまたがる結合セル

- 複数列にまたがる結合セルだけを含む行は、安全に行単位で移動できる場合は移動できる。

## 6. 移動先と結果

- 利用者が有効な移動先を確認できること。
- 移動できない行や位置を有効な移動先として扱わないこと。
- 有効な別位置への移動を確定した場合だけ Table の行順を更新すること。
- キャンセルまたは無効な移動では Table のデータを変更しないこと。

具体的な移動先の表示、確定、キャンセル、移動不能状態の見せ方は基本設計で定義する。

## 7. アクセシビリティ要件との分離

アクセシビリティ上追加で何を満たす必要があるかは、Table Reorder アクセシビリティ要件定義書で定義する。

主に次を扱う。

- キーボードだけで並べ替えを完了できること。
- PC・タッチともに、ドラッグを必要としない単一ポインター操作で並べ替えを完了できること。
- 移動可能な各行の並べ替え操作へ論理的な順序でアクセスできること。
- 操作中・操作後に操作対象や操作文脈を見失わないこと。
- 必要な操作案内を画面上で確認できること。
- 操作対象、操作状態、操作結果、移動できない理由を支援技術から確認できること。
- 本書で定義した移動制約をアクセシビリティ操作にも同様に適用すること。

具体的なキー割り当て、画面構成、操作フロー、フォーカス遷移、案内文、支援技術への情報提供方法などは基本設計で定義する。

## 8. 対象外

- 具体的な画面構成、操作入口、操作手順、表示方法の定義。
- キーボード、フォーカス、支援技術などアクセシビリティ固有要件の詳細定義。
- プログラム内部の構造や実装方法。
- Jest / Playwright テストの仕様。
- 並べ替えライブラリの選定や置き換え。
- 列の並べ替え。
- 複数行の同時移動。
- 行の複製。
- CSV 入出力。
- 値による自動ソート。

## 9. 完了条件

- WordPress Core Table と Flexible Table Block の本文行を対象としている。
- 対応する Table ブロックの本文行を同じ本文領域内で並べ替えられる。
- PC とタッチで本文行を並べ替えられる。
- 通常の Table 編集とスクロールを不必要に妨げない。
- 複数行にまたがる結合セルの範囲内の行そのものは移動できない。
- 複数行にまたがる結合セルの範囲の途中へ別の行を挿入できない。
- 結合範囲外の行は、結合範囲全体を越えて前後へ移動できる。
- 複数列にまたがる結合セルだけを含む行は、安全に行単位で移動できる場合は移動できる。
- 移動後もセル内容、セル属性、装飾を保持する。
- 有効な別位置への移動だけを確定する。
- キャンセルまたは無効な移動では Table のデータを変更しない。
- 一回の行移動を一回の Undo 操作として扱う。
- iframe・non-iframe の両方を対象とする。
- 要件は利用者に提供する機能、保証する振る舞い、利用上の制約に留まり、具体的な操作手順や実装方法を含まない。
- アクセシビリティ上追加で満たす必要がある性質は別文書へ分離している。
