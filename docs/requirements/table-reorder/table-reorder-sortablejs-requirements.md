# SortableJS版 Table Reorder 要件定義書

## 1. 目的

WordPress GutenbergのコアTableブロックについて、セル内容をコピーし直すことなく、本文行を安全に並べ替えられるようにする。

本書はSortableJS版Table Reorderの基本要件を定義する。実装内部ではなく、利用者から見える振る舞いを対象とする。

キーボード操作、フォーカス管理、スクリーンリーダー通知などのアクセシビリティ固有要件は別文書で定義する。

## 2. 対象範囲

- コアTableブロックの本文（`tbody`）内の行を対象とする。
- `thead`、`tbody`、`tfoot`をまたぐ移動は行わない。
- Table以外のブロックや、並べ替え対象ではないTableブロックへ影響を与えない。
- iframe・non-iframeの両方で同じ基本要件を満たす。

## 3. dnd-kit版からの主な変更

| 項目 | dnd-kit版 | SortableJS版 |
|---|---|---|
| PCの並べ替え開始 | ツールバーの「行を並べ替え」を押す | 並べ替えモードを使用しない |
| PCの通常状態 | ハンドル非表示 | 行左端の操作領域へのhoverでハンドル表示 |
| PCのドラッグ | 並べ替えモード中にハンドルをドラッグ | hoverで表示されたハンドルを直接ドラッグ |
| PCの並べ替え終了 | 明示的な終了操作が必要 | 終了操作なし |
| タッチの並べ替え開始 | 並べ替えモード | 並べ替えモード |
| タッチのドラッグ | ハンドル中心 | 行を長押ししてドラッグ |
| ハンドル配置 | Table外側の操作UI | 先頭セル左側の操作領域 |
| 複数行にまたがる結合セルを越える移動 | 不可 | 結合範囲全体を越えて前後へ移動可能 |

## 4. 共通要件

| ID | 項目 | 要件 |
|---|---|---|
| FR-01 | 行の並べ替え | `tbody`内の本文行を同じ`tbody`内の別の位置へ移動できる。 |
| FR-02 | 対象範囲 | `thead`、`tbody`、`tfoot`をまたぐ移動を行わない。 |
| FR-03 | データ保持 | 移動後もセル内容、セル属性、装飾を保持する。 |
| FR-04 | Undo | 一回の行移動を一回のUndo操作として元に戻せる。 |
| FR-05 | 確定 | 有効な移動を確定した場合だけTableの行順を更新する。 |
| FR-06 | 無効操作 | キャンセルまたは無効な移動では表データを変更しない。 |
| FR-07 | 編集環境 | iframe・non-iframeの両方で同じ基本要件を満たす。 |
| FR-08 | 影響範囲 | Table以外のブロックや対象外のTableブロックへ影響を与えない。 |

## 5. PC操作

PCはhover可能な環境を指す。

| ID | 項目 | 要件 |
|---|---|---|
| PC-01 | 並べ替えモード | PCでは並べ替えモードボタンを表示しない。 |
| PC-02 | ハンドル表示 | 行左端の操作領域へhoverしたとき、その行のドラッグハンドルを表示する。ただし、複数行にまたがる結合セルの範囲内の行には表示しない。 |
| PC-03 | ドラッグ開始 | 表示されたドラッグハンドルからポインターDnDを開始できる。 |
| PC-04 | ハンドル非表示 | hover対象から離れた場合は、ドラッグ中を除きハンドルを非表示にする。複数行にまたがる結合セルの範囲内の行ではhoverしてもハンドルを表示しない。 |
| PC-05 | 終了操作 | 並べ替え終了のための明示的なモード解除操作を要求しない。 |

## 6. タッチ操作

| ID | 項目 | 要件 |
|---|---|---|
| TOUCH-01 | 並べ替えモード | 「行を並び替え」ボタンで並べ替えモードを開始・終了できる。 |
| TOUCH-02 | ドラッグ開始 | 並べ替えモード中は行を長押ししてドラッグできる。 |
| TOUCH-03 | 通常編集 | 短いタップなど、ドラッグ開始に至らない操作では通常のセル編集へ移行できる。 |
| TOUCH-04 | 移動不可行 | 複数行にまたがる結合セルの範囲内の行を長押しした場合はドラッグを開始しない。 |
| TOUCH-05 | エラー表示 | 複数行にまたがる結合セルの範囲内の行を長押しした場合は、移動できないことを示すエラーメッセージを表示する。 |

## 7. 結合セルの保護

### 7.1 複数行にまたがる結合セル

- 複数行にまたがる結合セルの範囲内の行そのものは移動対象にしない。
- PCでは複数行にまたがる結合セルの範囲内の行にドラッグハンドルを表示しない。
- タッチ端末では複数行にまたがる結合セルの範囲内の行を長押ししてもドラッグを開始せず、移動できないことを示すエラーメッセージを表示する。
- 複数行にまたがる結合セルの範囲の途中へ別の行を挿入できない。
- 結合範囲外の行は、結合範囲全体を越えて前後へ移動できる。
- 結合範囲を越える場合でも、結合範囲の途中を移動先として確定しない。
- 禁止された操作では表データを変更しない。

### 7.2 複数列にまたがる結合セル

- 複数列にまたがる結合セルだけを含む行は、安全に行単位で移動できる場合は移動を禁止しない。

## 8. ドラッグ中の表示

- 有効な移動先を視覚的に確認できる。
- 複数行にまたがる結合セルの範囲の途中は移動先として扱わない。
- 結合範囲外の行は、結合範囲全体を越えた有効な位置へ移動できる。
- ドラッグ確定時だけTableの行順を更新する。
- キャンセルまたは無効な移動ではデータを変更しない。

## 9. アクセシビリティ要件との分離

アクセシビリティ上**何を満たす必要があるか**は、SortableJS版アクセシビリティ要件で定義する。

具体的なキー割り当て、フォーカス遷移、UI、操作フロー、状態遷移、案内の表示条件・文言、ARIA属性、スクリーンリーダー通知のタイミング・方法など、**どのように実現するか**は #199 のアクセシビリティ基本設計または実装側で扱う。

SortableJS版アクセシビリティ要件では、例えば以下を扱う。

- キーボードだけで並べ替えを完了できること
- PC・タッチともに、ドラッグを必要としない単一ポインター操作で並べ替えを完了できること
- 移動可能な各行の並べ替え操作へ論理的な順序でアクセスできること
- 操作中・操作後に操作対象や操作文脈を見失わないこと
- 操作対象、操作状態、操作結果、移動できない理由を支援技術から確認できること
- 基本要件で定義された移動可否判定をアクセシビリティ操作にも同様に適用すること

## 10. 対象外

- アクセシビリティ要件の詳細定義
- アクセシビリティの具体的なキー割り当て、フォーカス遷移、UI、通知方法などの基本設計
- 基本設計書の作成・更新
- 実装計画書の作成・更新
- TypeScript / CSS等の実装方法
- Jest / Playwrightテストの仕様
- SortableJSそのものの置き換え
- 列の並べ替え
- 複数行の同時移動
- 行の複製
- CSV入出力
- 値による自動ソート

## 11. 完了条件

- PCでは並べ替えモードボタンを前提としない。
- PCではhoverによるハンドル表示とポインターDnDを行える。
- PCでは複数行にまたがる結合セルの範囲内の行にドラッグハンドルを表示しない。
- タッチ端末では並べ替えモード中に長押しDnDを行える。
- タッチ端末では複数行にまたがる結合セルの範囲内の行を長押しした場合、ドラッグを開始せずエラーメッセージを表示する。
- 複数行にまたがる結合セルの範囲内の行そのものは移動できない。
- 複数行にまたがる結合セルの範囲の途中へ別の行を挿入できない。
- 結合範囲外の行は、結合範囲全体を越えて前後へ移動できる。
- 移動後もセル内容、セル属性、装飾を保持する。
- 一回の行移動を一回のUndo操作として扱う。
- 複数列にまたがる結合セルだけを含む行は、安全に移動できる場合は許可する。
- iframe・non-iframeの両方を対象とする。
- アクセシビリティ上何を満たす必要があるかは別文書へ分離し、具体的な実現方法は #199 へ分離する。
