# Internationalization

Yamabiko Table Reorder の翻訳ファイルは `languages/` で管理します。

## 生成フロー

TypeScript / TSX は、まず `@wordpress/scripts` で WordPress が実際に読み込む JavaScript へビルドします。その後、WP-CLI の i18n コマンドで翻訳文字列を抽出・更新します。

```bash
npm run i18n
```

このコマンドは次の順に実行されます。

1. `npm run build`
2. `wp i18n make-pot` で `yamabiko-table-reorder.php` と `build/editor-extensions/table-reorder/index.js` から POT を生成
3. `wp i18n update-po` で既存の日本語訳を維持しながら PO を POT に同期
4. `wp i18n make-json` で JavaScript 実行時に WordPress が読み込む Jed JSON を生成

TypeScript ソースを WP-CLI に直接解析させないのは、ビルド後の JavaScript を翻訳抽出の基準にすることで、抽出対象と `wp_set_script_translations()` が実際に読み込むスクリプトを一致させるためです。

## ファイルの役割

- `languages/yamabiko-table-reorder.pot`
  - 翻訳対象文字列のテンプレートです。
  - ソースコードから再生成できます。
- `languages/yamabiko-table-reorder-ja.po`
  - 日本語翻訳の正本です。
  - `msgstr` の日本語訳はこのファイルで維持します。
- `languages/yamabiko-table-reorder-ja-<hash>.json`
  - JavaScript 実行時に WordPress が読み込む生成物です。
  - ファイル名の hash は翻訳対象 JavaScript の相対パスから WP-CLI が生成します。

## Git 管理

POT / PO / JSON はすべて Git 管理対象です。

- POT は翻訳対象の変更をレビュー可能にするためコミットします。
- PO は日本語訳の正本なので必ずコミットします。
- JSON は配布 ZIP に含まれる実行時成果物なのでコミットします。
- `build/` 自体は引き続き Git 管理対象外です。

翻訳文言を追加・変更した場合は `npm run i18n` を実行し、POT / PO / JSON の差分をまとめて確認してください。
